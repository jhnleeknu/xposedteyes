# 복구 절차

## 1. 앱 안에서 (권장, 즉시 적용)

| 동작 | 위치 | 효과 |
|---|---|---|
| 신규 기능 전체 끄기 | 고급/진단 | 시작 앱·BT 실행을 즉시 중지하고 대기·재시도 작업 취소 (SystemUI 에 변경 알림, 실행 시점에도 다시 확인) |
| 자동 실행 OFF | 시작 앱 관리 | 시작 앱 대기·재시도 즉시 취소 |
| 블루투스 연결 시 실행 OFF | 시작 앱 관리 | BT 예약 취소 |
| 기본값 복원 | 시작 앱 관리 / 고급 | 해당 설정 기본값 + 대기 작업 취소 |
| 신규 기능 전체 기본값 복원 | 고급/진단 | 시작·BT·진단 설정 기본값, 전체 끄기 해제 |
| 설정 가져오기 | 고급/진단 | 검증 통과한 파일만 적용, 실패 시 아무것도 바꾸지 않음 |

마이그레이션 직전 설정은 앱 내부 `files/settings_backup_pre_v1.json` 에 자동 백업된다(같은 형식이라 *설정 가져오기* 로 되돌릴 수 있다. 단 3.0 키 외 신규 키는 포함되지 않는다).

CarPlay 화면·BT 마이크는 현재 **어떤 값도 적용하지 않으므로** 되돌릴 변경이 없다. 진단 로그 옵션은 읽기 전용이며 끄고 해당 앱을 재시작하면 훅이 설치되지 않는다.

## 2. 반복 오류 자동 정지

SystemUI 의 시작 앱 엔진은 내부 오류가 3회 발생하면 그 프로세스 동안 스스로 정지하고(`ENGINE_DISABLED`) 앱의 *최근 실행 결과* 와 LSPosed 로그에 남긴다. 클래스/메서드가 없는 펌웨어에서는 해당 훅만 건너뛰고(`BluetoothControl not found`) SystemUI 는 원래대로 동작한다.

## 3. 앱을 열 수 없을 때

1. LSPosed 관리자 > 모듈 > XposedTeyes 비활성화 또는 SystemUI 범위 해제 → 재부팅.
2. LSPosed 관리자도 열 수 없으면 adb 루트 셸에서 Magisk 모듈(LSPosed)을 비활성화한다. 경로·방법은 설치한 Magisk/LSPosed 버전 문서를 따르며, 일반적으로 `/data/adb/modules/<lsposed 모듈 디렉터리>/disable` 파일 생성 후 재부팅이다. **이 절차는 CC3 에서 검증하지 않았다(NOT_TESTED).**
3. 시작 앱 엔진의 부팅별 상태는 SystemUI 의 기기 보호 저장소(`/data/user_de/0/com.android.systemui/shared_prefs/xposedteyes_startup_state.xml`)에 있다. 지우면 다음 부팅부터 새로 시작한다. 이 파일에는 부팅 식별값만 있으며 외부로 보내지지 않는다.

모듈 기반(Magisk·Zygisk·LSPosed) 자체의 부팅 장애를 이 앱이 자동 복구한다고 보장하지 않는다. 설치 전 위 2번 절차를 자신의 환경에서 먼저 확인할 것.

## 4. 3.0 으로 되돌리기

서명이 달라 덮어쓰기 설치가 안 된다(docs/BUILD.md). 앱 삭제 → 3.0 APK 설치 → LSPosed 재설정. 3.0 이 쓰던 키(`launchOnStartup`, `launcherMusicApp` 등)는 마이그레이션에서 지우지 않으므로, 설정 백업 파일을 보관했다면 값을 다시 입력할 수 있다.
